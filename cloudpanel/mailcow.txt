CATATAN MAILCOW + CLOUDPANEL + CLOUDFLARE

Dokumentasi instalasi dan konfigurasi Mailcow pada server CloudPanel.

STATUS DOKUMEN

Dokumen ini menggantikan catatan lama “mailu.txt” yang sudah usang.
Setup saat ini menggunakan MAILCOW, bukan Mailu.

Tanggal dokumentasi: 17 September 2026

================================================
1. TOPOLOGI SERVER
================================================

Server: - Public IP: 103.127.xxx.xxx - Host Mailcow:
mail.mucharaya.com - Mailcow directory: /opt/mailcow-dockerized -
CloudPanel sudah terpasang pada server - Cloudflare digunakan sebagai
DNS - CloudPanel tetap mengelola web port 80/443 - Mailcow web service
tidak langsung memakai public port 80/443

Arsitektur:

Internet | | HTTPS v Cloudflare | v CloudPanel :80/:443 | | Reverse
Proxy HTTPS v 127.0.0.1:7443 | v Mailcow nginx | +– SOGo Webmail +–
Mailcow UI +– PHP-FPM +– Rspamd +– dll

SMTP/IMAP: Internet | +– SMTP 25 ——> Mailcow Postfix +– SMTPS 465 —->
Mailcow Postfix +– Submission 587 -> Mailcow Postfix +– IMAP 143/993 ->
Mailcow Dovecot +– POP3 110/995 -> Mailcow Dovecot

================================================
2. KONFIGURASI MAILCOW
================================================

Lokasi:

cd /opt/mailcow-dockerized

File konfigurasi:

/opt/mailcow-dockerized/mailcow.conf

Konfigurasi penting:

MAILCOW_HOSTNAME=mail.mucharaya.com

HTTP_PORT=7080 HTTP_BIND=127.0.0.1

HTTPS_PORT=7443 HTTPS_BIND=127.0.0.1

ENABLE_IPV6=false

Catatan: - Mailcow HTTP internal: 127.0.0.1:7080 - Mailcow HTTPS
internal: 127.0.0.1:7443 - CloudPanel reverse proxy mengarah ke HTTPS
127.0.0.1:7443 - Jangan mengubah konfigurasi ini tanpa memahami konflik
port dengan CloudPanel.

================================================
3. VALIDASI KONFIGURASI MAILCOW
================================================

Sebelum menjalankan Mailcow:

docker compose up -d

Melihat status:

docker compose ps

Melihat log:

docker compose logs -f

atau per service:

docker compose logs -f nginx-mailcow docker compose logs -f
postfix-mailcow docker compose logs -f dovecot-mailcow docker compose
logs -f sogo-mailcow

6. PTR / REVERSE DNS
================================================

IP: 103.127.xxx.xxx

Hostname yang diinginkan:

mail.mucharaya.com

PTR aktual sebelumnya: ip-161-138-127-103.wjv-1.biznetg.io.

PTR tidak dikelola melalui DNS forward zone mucharaya.com.

Jika suatu saat ingin memperbaiki PTR: minta provider/IP owner (Biznet)
mengatur reverse DNS:

103.127.xxx.xxx -> mail.mucharaya.com

Untuk setup ini PTR sengaja tidak dijadikan blocker dan tidak digunakan
sebagai syarat melanjutkan konfigurasi.

JANGAN membuat record palsu seperti:

161.138.127.103.in-addr.arpa

di zone normal mucharaya.com dengan asumsi itu otomatis mengubah PTR.
Reverse DNS harus berada pada reverse zone yang memang
dikelola/delegasikan oleh pemilik blok IP.

================================================
10. SPAM / DELIVERABILITY
================================================

Pada tahap awal email dapat masuk ke Spam Gmail.

Ini tidak berarti konfigurasi SPF/DKIM/DMARC salah.

Untuk domain/server baru: - reputasi IP belum terbentuk - reputasi
domain belum terbentuk - volume pengiriman masih rendah - Gmail dapat
menempatkan email baru di Spam

Jangan mengubah SPF/DKIM/DMARC yang sudah PASS hanya karena email masuk
Spam.

Lakukan warming secara normal: - kirim email yang memang diperlukan -
jangan melakukan bulk spam - penerima dapat menandai email sebagai “Not
spam” - gunakan mailbox secara normal

13. CATATAN TLSA
================================================

Mailcow dapat menampilkan record TLSA seperti:

_25._tcp.mail.mucharaya.com

Jangan membuat record TLSA secara asal.

Jika sedang berada di Cloudflare zone teunulehjournal.com, jangan
memasukkan:

_25._tcp.mail.mucharaya.com

ke kolom Name secara langsung.

Cloudflare akan menganggapnya sebagai:

_25._tcp.mail.mucharaya.com.teunulehjournal.com

yang salah.

Untuk konfigurasi saat ini: TLSA/DANE tidak diperlukan untuk membuat
email bekerja.

TLSA sengaja diabaikan.

docker inspect -f ‘{{.Name}} -> {{.HostConfig.RestartPolicy.Name}}’
$(docker compose ps -q)

Hasil yang sudah diverifikasi: - acme-mailcow -> always - clamd-mailcow
-> always - dockerapi-mailcow -> always - dovecot-mailcow -> always -
memcached-mailcow -> always - mysql-mailcow -> always -
netfilter-mailcow -> always - nginx-mailcow -> always - ofelia-mailcow
-> always - olefy-mailcow -> always - php-fpm-mailcow -> always -

redis-mailcow -> always - rspamd-mailcow -> always - sogo-mailcow ->

================================================
21. PRINSIP KONFIGURASI
================================================

-   Satu Mailcow dapat melayani banyak domain.
-   Setiap domain harus memiliki MX sendiri yang menunjuk ke mail
    server.
-   Setiap domain memiliki SPF sendiri.
-   Setiap domain memiliki DKIM sendiri.
-   Setiap domain memiliki DMARC sendiri.
-   Mail hostname tetap satu: mail.mucharaya.com.
-   Jangan membuat mail.teunulehjournal.com hanya karena domain baru
    ditambahkan.
-   Jangan menggunakan Cloudflare Proxy untuk hostname mail.
-   Jangan membuat DKIM secara manual jika Mailcow sudah menghasilkan
    key.
-   Jangan mengubah SPF yang sudah PASS tanpa alasan.
-   DMARC awal menggunakan p=none untuk monitoring.
-   TLSA/DANE tidak diperlukan untuk setup dasar ini.
-   PTR tidak dijadikan blocker dalam setup ini.
